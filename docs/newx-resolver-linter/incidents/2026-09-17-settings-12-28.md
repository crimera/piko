## Failure

Before the fix, the exact command failed in `NewX: Browse tweet object` with:

```text
Failed to match fingerprint: ComposeSettingsBasicItemCallerFingerprint
at app.crimera.patches.newx.settings.SettingsPatchKt.newXSettingsPatch$lambda$0$0(SettingsPatch.kt:45)
```

The renderer descriptor itself is present in the target APK as:

```text
Lcom/x/settings/common/a;->e(Ljava/lang/String;Ljava/lang/String;Lcom/x/icons/b;Lkotlin/jvm/functions/Function0;Landroidx/compose/ui/Modifier;JJLandroidx/compose/runtime/Composer;II)V
```

The important drift is that 12.28 no longer has an in-package
`Lcom/x/settings/common/` caller for this renderer. The older 12.27 shape has
such a caller (`common/z->invoke`), so requiring the caller fingerprint made
the settings patch fail even though the row renderer remained available.

## Fix

- Removed the exact generated Compose parameter-list constant from the caller
  and renderer resolution.
- Added a semantic row-layout resolver for the title, summary, icon,
  click-handler, modifier, color-long pair, composer, and trailing flag slots.
- Kept the caller-derived renderer path for older releases and added a direct
  scoped renderer fallback for releases whose lowering omits that caller.
- Derived the injected register moves and original `invoke-range` end from the
  resolved parameter layout.
- Added 12.28.0-alpha.01 to the centralized NewX compatibility targets.

`SettingsContributionPatch` remains unchanged because it only depends on and
registers contributions after `newXSettingsPatch` has resolved the shared row;
the fix is therefore centralized in the renderer patch.
